ahead of the CNJ improbidade-registry import. This records every finding, what

## Fixed in the frontend/backend waves — LANDED and vetted this pass

- **Réu-vs-citado everywhere.** `DEFENDANT_IN` renders the edge *type* ("Réu em")
  on indexed pages for people who were merely *cited* (`outcome: "cited"`). Only
  `/processo/[id]` hedged it. Fix: render from `edge.outcome`, never the edge
  type; "Réu" only for a human-confirmed outcome. (`GraphLegend`, `DetailPanel`,
  `EntityUI`, `/escandalo`.)
- **Empty-record politician titles.** `/politico/[id]` `<title>` asserts
  "processos, sanções e escândalos" even for a politician with zero of each, and
  all 4,882 are in the sitemap. Fix: title/description conditional on non-zero,
  or noindex empty profiles.
- **Scandal JSON-LD.** `/escandalo/[id]` emits private citizens as schema.org
  `Person` — the exact machine-readable name-indexing `/processo` refuses. Drop it.
- **Methodology contradiction.** metodologia says the project "não adiciona nem
  infere" while elsewhere labelling "uma inferência nossa". The first sentence is
  what a plaintiff's lawyer reads aloud. Reconcile to the truth (we DO infer, and
  we mark it).
- **"Empresa de fachada" / "Condenado" as bare fact.** `DetailPanel` prints a
  machine `type` as "Empresa de fachada" (per-se corporate defamation) and a
  case-level flag as a personal "Condenado". Hedge both.
- **Backoffice hardening.** CSRF (htmx custom-header gate) on state-changing
  POSTs; `reviewApprove` gated on `status == 'pending'` before any write; fail
  fast on the `changeme` default password when `DEV != true`.
- **Memgraph migrations** made re-runnable (IF NOT EXISTS), so a crash between
  running the DDL and recording the migration can't wedge startup.

## Performance — measured before AND after the fix

The fold-at-query-time search folded case+accents on every node of every search.
Fixed by precomputing the folded text at write time (`search_name` on the four
name-bearing labels; `search_text` on Sanction) and comparing against that, plus
bare label indexes. Migration `005_search_name`; every name-writer now sets the
folded field beside the name (fold.go documents the invariant). **Verified live
on the 131,840-node dev graph** — the numbers below are measured, not projected.

| Endpoint | Before | After | Cause / fix |
|---|---|---|---|
| `search?q=lula` (all labels) | 4.02s | **0.55s** | `MATCH (node)` all-scan folding each label's fields at query time. Name labels now hit `search_name`; sanctions hit `search_text`. |
| `search?q=…&type=person` | ~4s | **49ms** | name fold × all nodes → indexed label scan + plain CONTAINS on `search_name`. This was the import blocker (improbidade adds people). |
| `search?q=…&type=sanction` | 3.44s | **29ms** | folded registry/type/organ/process_ref × 64,779 → one CONTAINS on precomputed `search_text`. |
| `type=politician / org / scandal` | — | 57 / 10 / 2ms | `search_name` + cheap alias fold over the few thousand that have aliases. |
| all labeled `MATCH (:Label)` | full 131,840 scan | indexed | 6 bare label indexes (migration 005) — also helps `/scandals` ScanAll. |

Correctness re-verified: `jose` / `josé` / `JOSÉ` all return the same 40, `ceis`
still finds sanctions by registry. Postgres healthy (poll 4ms). Frontend clean.

The four decisions below were the operator's call; all four are now landed and
verified live. Kept for the record — the "Options" text is the choice that was made.

- **D1 → mark ambiguous, stop aggregating.** A Person with no full CPF is flagged
  `ambiguous`; /pessoa shows a "nome comum — pode corresponder a mais de uma
  pessoa" banner and drops the schema.org `subjectOf` so the merged records are
  not asserted as one person's. Node ids unchanged. (commit "Flag name-only people…")
- **D2 → purge reaches the review tables.** Purge now also deletes the subject's
  name from `pending_review`, `djen_party_snapshot`, `pending_aliases`, logging
  the count. (commit "Complete LGPD erasure…")
- **D3 → aggressive normalization, auto-block.** `TombstoneKeyName` folds

  older than `CNPJ_REENRICH_DAYS` (default 90); never-stamped orgs backfill
  first. (commit "Re-enrich stale CNPJ organizations…")

## (Original decision framing kept below for context)

### D1. Homonym collapse (data-model change)
Name-only Person/Organization node ids are derived from the normalized NAME
(`djenPersonID`, `qsaPersonID`, `djenOrganizationID`). Two different real people
named "José Carlos de Souza" **collapse into one node** accumulating both their
cases; DJEN carries no document, so it is silent and guaranteed for common names.
The public `/pessoa` page then shows one man connected to another man's case.
Options: (a) key per-observation (comunicação/case id in the node id) — splits
duplicates, loses aggregation; (b) mark these nodes ambiguous and suppress
cross-case aggregation on `/pessoa`; (c) require ≥2 corroborating signals before
merging. This changes how 19,416 nodes are identified — your call before I touch it.

### D2. Purge completeness (LGPD art. 18)
A purge scrubs the graph + tombstone but leaves the person's NAME in
`pending_review.payload`, `djen_party_snapshot.nome`, and `pending_aliases`.
Bounded fix (delete matching rows on purge) — but confirm you want purge to reach
those tables, since they are the review/audit substrate.

### D3. Tombstone is exact-string
Anti-resurrection keys on the exact normalized name, so a purged "JOSÉ DA SILVA
JUNIOR" reappears as "JOSE DA SILVA JR." unblocked. Looser fingerprint or
review-on-near-match — a matching-policy decision.

### D4. CNPJ enrichment is write-once
An enriched Organization is never re-fetched, so `active`/dissolved status and
ownership freeze forever. Same staleness class as R0 but for companies. Fix is a
re-enrich cursor; needs a cadence decision.

## Operational / deployment (runbook, not repo code)

These bite on a real server, not in dev compose:

- **Exposed unauthenticated DBs.** Prod compose maps `5432`, `7687`, `7444` to the
  host; Memgraph runs auth-less. Anyone reaching the IP gets full read/write
  Cypher — every CPF, or `DETACH DELETE`. Bind `127.0.0.1`, enable Memgraph auth.
- **No TLS.** API, backoffice basic-auth, and CPFs travel cleartext. Put a TLS
  terminator in front.
- **No external backup.** Only local Docker volumes. Human-entered per-defendant
  outcomes exist ONLY in Memgraph and are not re-derivable. Scheduled `pg_dump` +
  Memgraph snapshot off-box.
- **Defaults ship dev-shaped.** `.env.example` has `DEV=true`, `SEED_BASELINE=true`,
  `changeme`. Flip in the example; assert non-dev at prod boot.
- **No per-run record** for datajud/djen/cnpj/sanctions (they log stats to stdout
  only). An operator can't query "did last night's run write anything". Persist a
  run row per ingest worker.
- **Swagger UI is public and ungated.**

### Caching strategy (decided 2026-07-17): no Redis

Considered and rejected. Public traffic never touches Postgres (all public
routes read Memgraph; Postgres serves workers + backoffice at ~4ms/query), and
Memgraph is already the in-memory store — a Redis in front of it would cache
memory with more memory while adding an invalidation problem and another
container to operate. The expensive part was query *computation*, and that was
fixed at the source (search_name/search_text, label indexes).

The layers that exist instead, cheapest first:
1. **Next ISR** — every entity page `revalidate = 3600` (already there).
2. **React Query** — client-side staleTime 5 min (already there).
3. **`Cache-Control: public, max-age=300, stale-while-revalidate=3600`** on all
   public `/api/v1` GETs (added; backoffice deliberately uncached), so browsers
   revisit for free and any reverse proxy can micro-cache.
4. **At deploy**: the TLS terminator this runbook already requires (Caddy/nginx)
   can honor those headers as a shared micro-cache — still no new stateful infra.

Revisit only if real traffic shows a hot endpoint that these layers miss; the
first tool then is an in-process Go TTL map on that one query, not Redis.
